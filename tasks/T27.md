# T27 · 不可变数据集快照与可校验交付

冻结数据集快照并生成可校验交付，保证后台导出不受后续编辑影响。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-backend`。**前置:** T14, T26。**互斥域:** datasets, export-ui。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** C6/C7、T14formats、T26review，以及固定media/ontology/revision。

**交付内容：** 提供原生/YOLO/COCO快照导出、稳定类别映射、group split、loss报告、授权下载和幂等导出。

## 验收时逐项检查

1. snapshot固定r8后，即使后台导出时新增r9，也不能改变结果内容hash。
2. 同一snapshot重试时，内容、类别映射和划分一致。ZIP时间戳固定，或比较manifest内容hash。
3. 有loss必须显式ack。不能静默丢弃属性或审核信息。
4. 缺媒体、错误hash、未审核范围和未确认negative应阻止导出，或按预览清单排除，不能自动漏掉。
5. 拒绝跨project下载及猜ID访问。原生包不得包含密钥或运行路径。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 先在DB事务内冻结datasetitems，之后worker只读snapshot。exporter_version和params写入manifest。
- [ ] split使用固定seed和source_group，不在每次导出时随机。避免同来源组跨train/val/test。
- [ ] 导出canonicalPNG和对应标签。用assetID命名防冲突，并保留original_name元数据。
- [ ] 保存manifest、statistics、validation、loss_report和hashes。遵守ZIP总量预算和安全路径限制。
- [ ] 用独立loader读取并回显bbox，不能只检查压缩包存在。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。
