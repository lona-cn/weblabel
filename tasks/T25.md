# T25 · 模型全链路、外发授权与差异化AI关卡

验收模型输入授权、候选与接受保存的完整链路，将工程验证与真实模型关卡分开。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-ai`。**前置:** T18, T20, T23, T24。**互斥域:** ai-integration, consent。T22 当前为退役/历史保全，不再是活动 Codex 接入依赖。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** T16–T24实际模块、C4/C5、SaveRequest事务intents，以及G2。

**交付内容：** 打通flush→freeze→preview/consent→run→严格候选校验→diff→accept→save→undo。所有渠道必须遵循同一业务语义。

用户已批准将公开profile列表和consent创建服务前置，串行归入T24，避免T24→T25→T24的归属环。本任务仍负责实际project policy/scope重新校验、profile与fingerprint变更后的失效、全渠道编排及T32实测。已有consent意图记录不能当作外发许可。

## 验收时逐项检查

1. consent批准图像hash/profile/crop后，任一改变都使原consent失效。非外发检测无需云授权，但下载权重仍需授权。
2. AI运行前必须等待flush成功。冲突或本地尚未持久化时，阻止基于错误版本运行。
3. raw prediction与正式annotation隔离。accepted decision和revision在同一事务中提交。
4. mock工程演示必须明确标记。真实profile不能连接fake process或返回固定JSON。
5. 取消、超时、额度不足或模型不存在时，不自动重试计费。context不能因切图而错写。

下面给出核心测试的输入和断言起点，不能替代完整验收。优先复用公共测试fixture。若需要新helper，应在本任务内实现，并写明精确类型。

JSON块描述测试条件，不是运行结果。代码片段中的场景变量，需要按前述步骤在测试Arrange段准备。最终必须验证实际行为，不能用注释或静态常量检查代替。

```ts
import {expect,it} from 'vitest';
import {matchesConsent} from '../../apps/web/src/features/ai/runCoordinator';
it('invalidates consent when input fingerprint changes',()=>{
 expect(matchesConsent({approved_fingerprint:'sha-A'}, {input_fingerprint:'sha-B'})).toBe(false);
 expect(matchesConsent({approved_fingerprint:'sha-A'}, {input_fingerprint:'sha-A'})).toBe(true);
});
// 同文件必须通过真实HTTP重复该检查，UI断言不能替代服务端授权。

```

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。

- [ ] input_fingerprint包含媒体内容、区域、参数、模型profile版本、规范版本和提示。不包含无关动态UIstate。
