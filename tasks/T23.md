# T23 · 官方Claude订阅/Sonnet运行时适配

接入官方 Claude 订阅及 Sonnet 运行时，与 Anthropic API 渠道明确分开。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-ai`。**前置:** T02, T21。**互斥域:** native-runtime, claude-adapter。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** T02固定官方headless合同、S6/S7，以及T16/T21。

**交付内容：** 实现claude_local ProviderAdapter，使用原版Claude Code本人登录，展示Sonnet完整型号，并接入图像和MCP辅助。

## 验收时逐项检查

1. 可靠区分流式输出、工具结果和最终结果。截断JSON必须报错，不能误写标注。
2. 保留官方认证，费用由用户承担。不提供自建Claude.ai登录或token中转。
3. 实测官方工具allow/deny策略，限制命令注入、额外MCP和用户配置串入。
4. 账号、型号或订阅权限不符时，明确显示blocked或needs_login。API调用不得冒充订阅成功。
5. 真实图像运行由T32核验，synthetic只能测试解析和错误路径。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 使用本机官方CLI确认过的headless接口，不写未经证实的flags。固定版本并保存示例帮助输出。
- [ ] 按S6条件保留未修改运行时，系统不收集或保存登录凭证。文档区分个人订阅和API mode。
- [ ] 进程cwd为受限run目录，工具清单只包含MCP授权工具。文件系统边界无法验证时立即记录blocker。
- [ ] Claude返回的usage为空时记unknown。取消可能已经产生费用，UI不能宣称退款。
- [ ] API Anthropic adapter由T20实现，与订阅channel分为两个profile，不能共用假auth选项。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。
