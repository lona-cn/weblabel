# T19 · 候选校验、原子接受与可撤销来源

统一校验候选并支持原子接受、撤销与来源记录，避免过期结果覆盖人工编辑。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-core`。**前置:** T04, T17。**互斥域:** editor-core, suggestion-contract。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 验收时逐项检查

1. stale base/generation/hash/ontology/asset任一不符，都不能变更doc。
2. 拒绝超过1000上限、未知label、非法属性、非有限数、越界bbox和重复ID。
3. audit_attributes收到geometry/delete/create动作必须拒绝。检测create必须具备capability。
4. 批量中一项非法，整批不改。用户可显式接受子集；重复accept不能生成重复对象。
5. accept→undo→redo保留原prediction及历史。保存intents保持顺序，并在事务内原子提交。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 校验逻辑放在domain，供native/wasm共享。不要在浏览器和API各写一套可能漂移的规则。
- [ ] 用change_ids显式选择，expected_generation为当前内核generation。版本或对象改变后不得自动rebase。
- [ ] UI可展示stale旧建议，但只有重新运行或针对新context明确重校验后才允许接受。
- [ ] apply_suggestions聚合普通命令，history保存逆向before，并生成accept/revert intents。
- [ ] 将同样校验接入T11保存事务。集成完成前，非空intents不能临时绕过校验。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。
