# T02 · 官方运行时与模型接入探针

核验官方模型渠道的协议、认证和工具边界，为后续适配器提供有来源的依据。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-researcher`。**前置:** T00。**互斥域:** provider-research。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** S5–S7、S11–S12，以及本机实际可用的codex/claude --version/--help。用户未授权时，不得登录或调用付费API。

**交付内容：** 为每个渠道记录固定官方来源、真实协议生成命令、实际安装版本，以及图像和工具限制。未知字段设为null并说明原因。这些证据供T16/T20/T22/T23实现使用，不代表真实调用通过。

## 验收时逐项检查

1. 模型名、provider和auth通道分别记录。不能根据Sonnet/Luna/MiMo营销名猜测模型ID。
2. 核验Codex stdio握手、schema生成，以及Claude官方headless模式和工具限制。
3. 核验MiMo官方base URL及request/stream/cancel/usage；证据不足时明确说明。
4. 如果实际不支持安全的MCP工具限制，必须判blocked，不能建议逆向token。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 只读研究Agent负责提供报告。运行--help/schema探针和写文件由主Agent执行并保存日志，不给研究Agent任意shell权限。
- [ ] 以本机帮助输出为准，不套用旧教程。保存命令输出的版本、日期和schema SHA。
- [ ] 分别记录三种状态：文档已核验、协议fixture已测、live已测。后两种状态不能仅凭阅读打勾。
- [ ] MiMo文档或认证不可访问时，将T20对应适配器子项标blocked；其余渠道继续。T32不得用其他渠道替代。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。

## 本任务验收命令

T00完成后统一入口：`pnpm test:task T02`。它必须实际执行：

```text
node scripts/verify-plan.mjs --provider-evidence reports/T02/result.json
```

还必须通过受影响语言的格式、类型和contract检查。以下情况均不算通过：测试命令不存在、匹配0条测试、对应provider未启用，或测试全部skip。统一入口由T00先实现，再调用；不能形成递归。

## 交付证据与停止条件

交付 `reports/T02/result.json`、`tests.log` 和 `review.md`。涉及真实视觉验证时，附截图或trace；涉及模型时，附脱敏profile、输入hash和响应证据。

结果必须列出改动文件、实际base/commit、执行命令、测试数量、已知限制和外部阻塞。

只有同时满足以下条件，任务才能标done：全部行为符合要求、真实窄测试通过、审查没有阻断问题、commit已落地。

缺少账号或硬件的部分必须明确标blocked。工程任务完成不代表live/GPU关卡通过，不能顺手改成pass。检查失败时保留已经完成的文件，并说明下一步最小动作；不能重新初始化项目。
