## 测试输入与断言起点

以下是核心测试输入/断言，不是全部验收。测试类任务使用已有公共测试fixture；需要新helper时同任务创建并给出精确类型。JSON块是测试条件，不是声称运行结果。片段中场景变量需按上文具体步骤在测试Arrange段创建，不能把注释或静态常量检查当最终行为测试。

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import {spawnSync} from 'node:child_process';
test('unknown task must fail', () => {
  const p = spawnSync(process.execPath, ['scripts/task.mjs','T99'], {encoding:'utf8'});
  assert.notEqual(p.status, 0);
  assert.match(p.stderr + p.stdout, /unknown task/i);
});
```

## 窄验收命令

T00完成后统一入口：`pnpm test:task T00`。它必须实际执行：

```text
node --test tests/bootstrap/t00.test.mjs
node scripts/verify-plan.mjs
cargo build -p renderer-wgpu --target wasm32-unknown-unknown --locked
pnpm test:e2e
```

还需通过受影响语言的格式/类型/contract检查。测试命令不存在、匹配0条、未启用该provider或测试仅skip时均不满足验收。T00本身先实现入口再调用入口，不形成递归。
