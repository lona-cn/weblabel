# T00 · 空目录启动、工具链与可执行测试入口

建立后续任务能直接使用的工具链、工作区和测试入口；本任务不实现业务功能。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `main`。**前置:** 无。**互斥域:** bootstrap。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** 执行包全部根文件、S1–S4、S8–S9，以及用户实际机器环境。

**交付内容：** 建立完整workspace空壳，固定工具链和锁文件，并提供统一pnpm命令。空壳本身不算功能完成；入口就绪后，从T01起应能独立执行窄测试。

## 验收时逐项检查

1. 在git空目录中保留执行包；若目录已有文件，不得覆盖。缺少身份信息时只记录问题，不伪造身份。
2. 任务不存在、测试零匹配、子进程失败或缺少Rust/Node时，命令都必须非零退出。
3. 编译并实际调用最小wasm+wgpu探针，初始化adapter/device。没有adapter/device时必须给出诊断，不能降级后宣称硬件性能通过。另用Node stdio探针校验版本化request/response。
4. OMP必须能列出自定义agents。只有确认实际隔离设置后，才允许并行执行。

## 本任务验收命令

T00完成后统一入口：`pnpm test:task T00`。它必须实际执行：

```text
node --test tests/bootstrap/t00_cli.test.mjs tests/bootstrap/verification.test.mjs
node scripts/verify-plan.mjs
cargo build -p renderer-wgpu --target wasm32-unknown-unknown --locked
pnpm test:e2e
```

还必须通过受影响语言的格式、类型和contract检查。以下情况均不算通过：测试命令不存在、匹配0条测试、对应provider未启用，或测试全部skip。统一入口由T00先实现，再调用；不能形成递归。

## 交付证据与停止条件

交付 `reports/T00/result.json`、`tests.log` 和 `review.md`。涉及真实视觉验证时，附截图或trace；涉及模型时，附脱敏profile、输入hash和响应证据。

结果必须列出改动文件、实际base/commit、执行命令、测试数量、已知限制和外部阻塞。

只有同时满足以下条件，任务才能标done：全部行为符合要求、真实窄测试通过、审查没有阻断问题、commit已落地。

缺少账号或硬件的部分必须明确标blocked。工程任务完成不代表live/GPU关卡通过，不能顺手改成pass。检查失败时保留已经完成的文件，并说明下一步最小动作；不能重新初始化项目。
