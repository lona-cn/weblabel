# T35 · 独立总审查、重放验收与发布状态

独立审查并重放全部必需验收，根据实际证据给出发布状态，完成后停止扩展。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `main`。**前置:** T31, T32, T33, T34。**互斥域:** release。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** 全部任务commit/evidence、G0–G5，以及独立wl-reviewer反馈。

**交付内容：** 只依据真实证据提供final release报告、已知限制、启动命令和剩余阻塞。不自动部署公网。

## 可修改的文件

- `reports/release.json`
- `reports/release-review.md`
- `reports/acceptance-matrix.md`
- `docs/known-limitations.md`
- `README.md`
- `STATUS.json`

花括号列出的是一组文件，不能把花括号本身写进文件名。通配符只允许在对应模块内新增文件。

根manifest、锁文件、router装配、导航和统一脚本注册均由主Agent独占。需要改动这些共享入口时，提交integration.patch，由主Agent串行集成。本卡列出文件范围，不等于授予共享文件的并行写权限。

## 验收时逐项检查

1. 从干净checkout按文档完成安装/build/test/start，不能依赖agent临时目录。
2. 所有必需关卡都有actualcommit和日志。缺少GPU/provider时不得标complete。
3. 源码不得含未授权secret、fake成功或disabled必需tests。契约生成必须无diff。
4. reviewer必须检查源草案映射、stale/ACK/EXIF/审核快照/权限，不能只看lint。
5. 生成全部交付文件的hash清单。README实际平台及provider矩阵必须与证据一致。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 主Agent复跑verify:fast/integration/browser/gpu/live/release。有费用且已授权的测试避免无谓重复；根据commit绑定的有效evidence判断重跑范围。
- [ ] final reviewer只读检查全diff和报告。阻断问题交owner或main，最小修复后重测。
- [ ] T31/T32blocked时，T35不能done。可以另给limited_preview报告和手工启动步骤，但不能宣称完整交付。
- [ ] 完成后停止派工，不自动进入Mask、视频或云端。向用户提供真实结果和可复现证据。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。

## 本任务验收命令

T00完成后统一入口：`pnpm test:task T35`。它必须实际执行：

```text
pnpm verify:release
```

还必须通过受影响语言的格式、类型和contract检查。以下情况均不算通过：测试命令不存在、匹配0条测试、对应provider未启用，或测试全部skip。统一入口由T00先实现，再调用；不能形成递归。

## 交付证据与停止条件

交付 `reports/T35/result.json`、`tests.log` 和 `review.md`。涉及真实视觉验证时，附截图或trace；涉及模型时，附脱敏profile、输入hash和响应证据。

结果必须列出改动文件、实际base/commit、执行命令、测试数量、已知限制和外部阻塞。

只有同时满足以下条件，任务才能标done：全部行为符合要求、真实窄测试通过、审查没有阻断问题、commit已落地。

缺少账号或硬件的部分必须明确标blocked。工程任务完成不代表live/GPU关卡通过，不能顺手改成pass。检查失败时保留已经完成的文件，并说明下一步最小动作；不能重新初始化项目。
