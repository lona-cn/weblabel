实现真实 wgpu 图像与矩形渲染，并让布局、资源更新和设备恢复可验证。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

## 验收时逐项检查

1. 实际创建texture/pipeline并执行draw。用640×480不对称基准图和已知bbox截图验证回显。
2. bbox边框和控制点保持固定屏幕宽度，不能随缩放变粗或变细。
3. canvas为0×0时不configure，恢复非零尺寸后重绘。device lost不能修改文档。
4. 实例buffer的offset/stride必须与WGSL完全匹配。dirtyrange更新和资源释放必须可测。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。

- [ ] 固定sRGB颜色和alpha混合路径。不要把已经混合的显示颜色写入训练语义。

- [ ] CPU布局测试与真实browser测试分开。完整画布要等T09/T15接入后验证；硬件性能另由T31验收。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。

## 本任务验收命令

T00完成后统一入口：`pnpm test:task T05`。它必须实际执行：

```text
cargo test -p renderer-wgpu --test t05_renderer --locked
pnpm verify:gpu
```

`pnpm verify:gpu` 必须先运行 `pnpm wasm:probe-build`，从当前 renderer 源码重建探针，不能使用陈旧 wasm。

随后设置真实适配器要求（REQUIRE_WGPU_DEVICE=1、REQUIRE_HARDWARE_GPU=1），运行 `tests/render/t05.spec.ts`，检查截图像素、缩放笔画和设备丢失恢复。软件 GPU 或没有适配器时必须失败，不得判为通过。

还必须通过受影响语言的格式、类型和contract检查。以下情况均不算通过：测试命令不存在、匹配0条测试、对应provider未启用，或测试全部skip。统一入口由T00先实现，再调用；不能形成递归。
