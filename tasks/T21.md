# T21 · 受限MCP语义工具与run级权限

提供 run 级受限 MCP 语义工具，让模型只能读取授权内容和提出候选。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**负责角色：** `wl-ai`。**前置:** T16, T19。**互斥域:** mcp, agent-tools-api。
**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 开始前要确认什么

**先读：** `AGENTS.md`、`docs/architecture.md`、`docs/contracts.md`、`docs/testing-contracts.md`、`docs/execution.md`。主Agent应在派工时提供当前契约hash、base commit，以及依赖任务的证据。以这些材料为准，不依赖聊天记忆。

**依据：** C5五工具、T17run、T19校验，以及独立短期run token。

**交付内容：** 实现官方Agent可消费的stdio MCP server。所有工具都绑定服务端冻结runcontext，只能提交建议。

根manifest、锁文件、router装配、导航和统一脚本注册均由主Agent独占。需要改动这些共享入口时，提交integration.patch，由主Agent串行集成。本卡列出文件范围，不等于授予共享文件的并行写权限。

## 验收时逐项检查

1. token过期、撤销或project不符时不能读取图或对象。sessioncookie不能代替run token。
2. read_region的坐标、数量和像素预算都受限，不能提供任意磁盘路径或URL。
3. propose_changes不能直接保存正式标注。accept/delete_file/shell等未知工具必须拒绝。
4. 图片、类别或规范中的提示注入不能扩大权限。工具参数带projectID必须拒绝。
5. 分页、重复调用、过大输入和空工具结果序列都应有可恢复处理。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 使用当前官方MCP SDK并固定版本。协议写stdout，日志写stderr。
- [ ] 图像以MCP图像内容块或官方支持的受限附件传递。文件路径只供内部grant使用，并保留canonical变换。
- [ ] run token由服务持有并限制工具集。用户取消后立即撤销，清理child环境和暂存目录。
- [ ] 工具描述要说明候选语义，但权限安全依赖服务端校验，不能依赖prompt。
- [ ] 接口形状完整写入JSON schema，设置additionalProperties=false。拒绝schema以外字段。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。
