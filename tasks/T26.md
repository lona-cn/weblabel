# T26 · 任务租约、版本审核与负样本语义

实现任务租约、版本审核和负样本语义，让审核始终绑定具体不可变版本。

这张卡是任务规格，不是当前通过声明。下列行为、验收命令和交付证据全部满足，并经审查与主 Agent 集成后，才算完成。

**外部实测关卡:** 否。若本任务包含真实外部调用，必须单独记录该子项的验证状态。

## 验收时逐项检查

1. lease60s、heartbeat20s。sleep、过期或旧fencing写入都必须拒绝，不能用CAS替代权限。
2. 审核批准r8后，新r9仍未批准；旧r8审核记录保留。
3. allow_self_review=false时拒绝同标注者审核。reviewer和viewer权限必须不同。
4. 空objects且unprocessed不能作为negative提交。显式confirmed_negative才可合法提交。
5. 规范变化或对象删除后，旧issue仍能追溯原revision。

## 怎样实施

- [ ] 开始前核对depends_on：所有依赖都应已done，且对应commit已经集成。再检查文件范围，确保可写路径不与其他在途任务重叠。
- [ ] 为每条必验行为准备自动测试，或明确的真实硬件/账号探针。先运行本任务的窄命令，记录功能未实现时的实际失败。环境错误和未收集到测试都不算Red测试。
- [ ] 任务lease与jobworkerlease不能共用表或token。转交时生成新fencing，不复用旧token。
- [ ] 提交时冻结媒体revision列表和ontology。审核展示不能读取动态head来替换审核对象。
- [ ] 批准或退回理由绑定具体revisionIDs。新编辑自动回到未提交状态。
- [ ] Web页面真实展示作业和审核差异，不能在localStorage中维护approved布尔值。
- [ ] 已分配任务的save一律强制lease。未分配本地草稿可按配置编辑，但仍必须CAS。
- [ ] 实现后复跑下面全部检查，保存完整输出、退出码、测试数和运行环境。不得为了通过而降低阈值、删除反例或注入固定成功响应。
- [ ] 提交规格审查和质量/安全审查。按实际diff修复问题，改动应尽量小；修复后由主Agent复跑目标测试。
- [ ] 将commit和结构化结果交给主Agent，由主Agent按本卡范围集成并更新STATUS。子Agent不能自行标done。
