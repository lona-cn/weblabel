## 验收时逐项检查

1. pan/zoom不能全量重传bbox，单对象edit只能更新局部range。
2. 2000/10000 boxes不得产生每对象DOM。idle10s不能持续GPUsubmit。
3. 100次切图后GPU/decoded计数稳定。超预算时必须明确拒绝或释放。
4. 隐藏、选择和锁定不触发远端保存，也不重算所有序列化文档。
5. 规范变更涉及大量对象时，只在逻辑提交处理，不能逐pointermovevalidate全部项目。

下面给出核心测试的输入和断言起点，不能替代完整验收。优先复用公共测试fixture。若需要新helper，应在本任务内实现，并写明精确类型。

JSON块描述测试条件，不是运行结果。代码片段中的场景变量，需要按前述步骤在测试Arrange段准备。最终必须验证实际行为，不能用注释或静态常量检查代替。

```ts
import {test,expect} from '@playwright/test';
test('idle canvas does not submit forever',async({page})=>{
 await page.goto('/test-harness/dense?count=2000&seed=17');
 await page.waitForFunction(()=>window.__wl_test?.ready===true);
 const a=await page.evaluate(()=>window.__wl_test!.stats().gpu_submissions);
 await page.waitForTimeout(1000);
 const b=await page.evaluate(()=>window.__wl_test!.stats().gpu_submissions);
 expect(b-a).toBeLessThanOrEqual(1);
});
// __wl_test只在测试build定义；T28给Window添加精确类型并在release tree-shake/拒绝路由。

```
