## 1. 基线与目标

基线提交：`f807d5092ad0998d425e11afafc5c10b36b0b813`。共享契约：现行 v1 及现有增量。原 36 项任务图结构检查通过，当前无 ready 任务；本计划是用户批准的新体验增量，映射原任务的维护范围，不重启或倒写历史任务。

目标不是堆叠工具，而是让使用者完成：准备项目 → 导入 → 连续标注 → 确认保存 → 独立审核 → 固定版本交付；遇到未知结果或故障时能保全工作并找到安全下一步。

四角色调查覆盖产品经理、标注人员、运维及销售。拖框时不可见是用户已确认问题，不重新运行检查来质疑用户观察。其他发现来自当前源码及前次独立合成数据界面观察；影响评估及建议不冒充真实用户访谈、当前完整验收或商业收益证据。前次界面包绑定 `81978b02433035d55a4fa48de43ae05b29b0ff13`，本次修复必须重新构建受影响模块。

已有撤销、数值几何、多类别/属性规范、密集选择、草稿分支救援、任务租约、不可变审核及导出损失报告。以下任务改进缺口和操作代价，不重造这些能力。

## 2. 边界与不得退化的行为

- 继续使用本机 loopback、桌面 Chrome/Edge、PNG/JPEG、轴对齐检测框与对象属性。视频、Mask、Polygon、云端、公网监听、实时共同编辑不在范围。
- Rust 是唯一可编辑几何来源；React 只消费投影。pointermove 只预览，不增加业务 generation、不读完整快照、不触发保存；一次 pointerup/批量变更一个 undo。
- canonical 连续像素坐标不加 1；DPR 不进入持久坐标。pan/zoom 不修改文档。
- 本地确认来自真实 IndexedDB transaction complete；服务器确认来自匹配原请求的 ACK。unknown 不等于失败，后续拒绝不证明原请求未提交；不自动重发未知写入。
- CAS、幂等、原作者、lease/fencing、草稿 lineage、候选 decision journal 同事务不因便捷操作而削弱。
- 空文档不是负样本；保存、完成、批准、可交付分别表达。审核绑定不可变 revision，新编辑不继承旧批准。
- AI 配置、可用性、工程测试及真实渠道验收分开。模型候选不自动覆盖人工；外发仍检查项目政策、真实 scope 和逐次授权。
- 不调用模型、不读取私人凭证、不下载权重、不上传业务图片、不推远端。实际渠道验收另需用户明确授权。
- 不改许可证，不授予再分发许可；签名安装器、自动升级、商业支持承诺另立范围。
- 所有自建工作树、缓存、合成数据与临时文件留在项目根内。保留当前用户改动、历史报告及删除的配置。

### 4.1 已冻结的跨切片契约

- 完成并继续：提交事务结束 lease；GET task submission 核对原身份和固定 revision，只证实目标状态，不证明未知 POST 的唯一归属。Main resolver 返回下一有权任务或 null，Panel 复用领取、安装、续期及 scope 屏障。
- 逐项拒绝：独立 immutable rejection operation/change tables，原 operation 换 payload 返回 409；接受事务检查逐项拒绝。原整组拒绝不伪装成逐项操作，多组部分结果逐项报告。
- AI provisioning：管理员从服务器固定 WEBLABEL_HOST_CONFIG 预设中选择 exact configuration_hash，绑定真实 adapter 身份和私有配置；浏览器不能提交 argv、endpoint、secret 或“已验证”状态。相同配置可核对，换配置不覆盖历史 profile。
- readiness：/health 保持 liveness；/ready 使用真实 SQL 与对象根读取，维护模式和故障为 503，无敏感路径。容量、锁及升级诊断保留本机管理员 CLI 边界，不增加公开敏感诊断 API。
- 导航：?project_id={id}&review_queue=all 打开有权任务/审核队列，不自动 claim 或假装定位未知 task；数据集修复入口固定真实 asset、ontology 和 revision。
- 证据：子切片测试通过不等于正式工作台已完成；历史 G4/性能/许可等阻塞独立保留。

## 5. 验证和完成定义

每个切片：读取规格与现状 → 针对缺口的失败行为测试（不是重复确认用户已报告的错误）→ 最小实现 → 窄回归 → 实际运行受影响路径 → 规格及质量/安全审查 → 主会话复跑 → 独立提交 → 更新状态和维护文档。

当前测试入口继续复用既有工具，不增加第二套框架：

- 原生手势：`cargo test -p editor-core --test t12_tools --locked`。
- 生命周期：`pnpm exec vitest run apps/web/src/lib/editor/t09_lifecycle.test.ts`。
- 属性/工作台：按定位选择现有 workbench 对应组件测试，加只覆盖混合值、批量作用范围、提交/取消及陈旧输入的行为回归。
- 保存：`pnpm exec vitest run apps/web/src/features/workbench/save-feedback.test.tsx apps/web/src/lib/persistence/t13_queue.test.ts`。
- 导入：`pnpm exec vitest run apps/web/src/features/import-export/panels.test.tsx`。
- 数据集：`pnpm exec vitest run apps/web/src/features/datasets/delivery-scope.test.tsx`。
