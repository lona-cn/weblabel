# 文档治理规范

读者：文档作者、模块维护者、主集成者和审查者。读后行动：选择正确文档类型，以可追溯来源完成修改、审查和结构检查。本文约束文档维护，不证明产品能力或发布通过；全部维护文档从[文档总入口](README.md)查找。

## 读者与读后行动

- 操作者：完成本地登录、导入、标注、保存、审核与导出；失败时保全未同步工作。
- 开发者：定位负责模块，迁移契约消费者，选择能覆盖变化的检查。
- 维护与验收者：配置成员、诊断故障、备份恢复，区分实现、实际验证和发布状态。

每份维护文档开头写读者、具体读后行动和验证边界。不能用“了解系统”代替可执行行动；不得要求读者知道此前聊天。已有完整教程继续维护，参考文档链接教程而不复制另一套简略流程。

## 文档分类及权威依据

类型固定为：入口、指南、参考、规范、运行手册、决策、计划、归档。

| 事实维度 | 权威依据 | 写作规则 |
|---|---|---|
| 安全边界与不变量 | 执行约束、现行共享契约 | 实现不足应注明差异，不能悄悄降低要求 |
| 设计目标与范围 | 架构、计划、任务卡、对应 ADR | 明确是目标，不能写成当前已验收 |
| 当前实现 | 当前 router、Rust 类型、生成契约、CLI | 核对真实字段、默认值、权限、错误；handler-local DTO 不冒充生成物 |
| 任务状态 | TASKS.json、STATUS.json、实际落地提交 | 不复制 36 行状态到文档目录；不因写文档升级任务或关卡 |
| 已验证能力 | 绑定 commit、输入/hash、命令/exit、运行条件的真实报告 | 历史观察只说明当时条件；未运行即未验证 |
| 模型来源 | [资料来源](sources.md)、provider 专题 | 不维护第二份 model_id 登记，不以搜索摘要代替官方资料 |

以上按事实维度判断，不是一个可覆盖所有事实的笼统优先级。规范与实现冲突时同时保留约束和已发现差异，交主集成者决策。

## 目录、命名、语言与 Markdown 格式

- 使用仓库 Markdown 与 Git，不新建文档站、托管服务或任务系统。
- 默认中文正文；CLI、字段、错误码、类型名保留真实字面值。
- 新专题放 docs，名称小写 kebab-case；ADR 沿用现有编号风格。既有路径不批量改名或搬迁。
- 每页一个一级标题，章节使用递进标题层级；命令围栏声明语言。步骤写完整输入、入口、观察和失败处理，不交付省略实现、空白专题或 TODO。
- 维护入链使用相对路径；锚点对应真实标题或显式 HTML id。图片必须有非空说明，截图只能包含获准的数据且清除启动码、密码、Cookie、CSRF 和凭证。
- 不在正文钉源码行号；以模块、符号、命令和契约章节定位。版本只在必要参考中固定，其他页链接固定工具说明。
- 文档目录在 [docs/README](README.md#文档目录) 的唯一六列表格中登记；不另建 JSON catalog，不给历史材料批量加 frontmatter。

## 元信息

目录列固定为 `文档 | 类型 | 读者与读后动作 | 维护责任 | 事实范围/权威依据 | 更新触发`。第一列链接具体现存 Markdown，其余列非空；维护责任使用现有角色（main、wl-backend、wl-core、wl-renderer、wl-web、wl-ai、wl-qa、wl-researcher），不是虚构个人姓名。

登记根入口与产品上下文、docs 下所有 Markdown（包括目录本身与原始草案）、三个 prompts 和 reports/index。任务卡只由 TASKS.json 的 card 字段登记；目录提供任务系统入口，不复制每张卡的状态。目录元信息区分当前说明、设计目标和历史观察；实际测试日期与环境放证据报告，不在目录声称自动“最新”。

## 变更触发与审查

路由、字段、默认值、权限、CLI、固定版本、状态机、故障恢复资格、目录路径或设计约束变化时，同批更新相关维护文档及维护入链。主集成者独占共享入口、manifest、lockfile、生成契约和 STATUS；模块作者修改自己负责专题，遵守[协作规程](execution.md)。

审查逐项检查：读者能否完成动作；输入是否齐全；来源是否支持陈述；成功观察是否具体；错误分支是否保全数据；权限、默认与字段是否真实；链接是否有效；历史与当前是否分开；未经实测的能力是否明确未验证。独立冷读者不靠作者解释补前提。结构检查通过不能取代事实审查与真实运行。

## 来源与验证口径

命令示例交付前实际执行，使用本轮项目内专属目录、合成输入和临时账号。不能运行的步骤明确 prerequisite blocker 与未验证行动，不用 mock、页面能开、软件 GPU、旧包或历史报告冒充本轮证明。外部 HTTP/HTTPS/mailto 链接结构检查不联网，其内容与版本由作者核验。

报告记录 base/integrated commit、命令 argv、exit、测试数量或 null、工具路径/版本、输入与产物 hash、设备条件、阻塞和授权边界。工程 source snapshot 不含 Markdown 时另记每份文档相对路径、SHA256 与字节数。文档 hash 只证明字节，不证明产品行为。

模型账户、权重、真实业务图与付费调用不因文档示例获得授权。不得读取私人配置或官方 CLI home；仅展示脱敏结构和 secret_ref 名称。

## 生命周期与归档

草拟文档完成事实核对、冷读与检查后成为维护文档；每次相关实现变更继续维护。失效决定在原文注明 superseded 与替代文档，保留原决定、原批准事实和证据。

历史计划、原始草案、报告、失败记录与原发行指纹不可倒写、删除或重算为新证明。需要物理归档时记录原路径、目标路径、原文字节 hash、原因，并同批迁移所有维护范围内入链；历史记录仍保留原时态。本轮不执行物理归档迁移。

## 可执行写作模板

以下是写作结构，复制后必须填写真实内容并删除不适用项；不是待交付的空白专题。

### 指南模板

```markdown
# 动作名称
读者：具体角色。读后行动：完成哪个结果。验证边界：已实测条件与未验证条件。
## 前提与输入
工具版本、权限、工作目录、允许使用的数据、参数取得方式。
## 执行步骤
1. 完整命令或页面入口；输入从哪里取得。
2. 下一步仅在前一步的可观察成功条件满足时运行。
## 验证结果
读取哪个状态/字段/文件，精确期望是什么。
## 失败恢复
先保全什么，如何诊断，允许什么，禁止什么，何时算恢复。
## 相关参考
链接当前字段契约、运行手册及真实证据。
```

### 参考模板

```markdown
# 接口或配置参考
读者：调用者或维护者。读后行动：正确构造输入并处理结果。验证边界：源码说明不等于运行通过。
## 生效入口与边界
作用域、权限、版本与所有者。
## 字段与默认值
表格逐项列真实字面名称、类型、默认/必填、边界和受管状态。
## 完整例子
完整输入、真实返回字段、如何取得 ID；不混用生成 DTO 与局部 DTO。
## 错误与未知结果
code、状态、保全与重放资格；不承诺所有底层错误已统一包络。
## 来源与消费者
现行契约、负责模块和需要同步迁移的消费者。
```

### 运行手册模板

```markdown
# 故障或运维动作
读者：维护者。读后行动：在不损失数据的条件下完成运维。验证边界：本次运行条件。
## 症状与真实 code
## 已确认与未知事实
## 先保全什么
## 诊断与允许动作
完整命令、权限、输出检查；未知 ACK 先只读核实。
## 禁止动作
不可删除、覆盖、自动重放或绕过的内容。
## 成功判据
逐项检查结果，不把页面打开当成数据已同步。
## 证据与相关契约
```

### ADR 模板

```markdown
# 编号：决定名称
## 状态
proposed / accepted / superseded；替代链接与日期。
## 背景
实际问题、约束与候选方案。
## 决定
采用方案、明确不采用什么及原因。
## 证据
官方来源、实际命令/输入/hash/条件、未验证边界。
## 契约影响
受影响的接口、不变量与全部消费者迁移要求。
```

沿用现有 ADR 的“状态、背景、决定、证据、契约影响”；只有新的实际决定才新建 ADR。

## 检查与交付

在项目根使用固定 Node 运行 `pnpm docs:check`。检查只负责目录登记、Markdown 出链、本地目标/锚点和图片说明，既不联网也不验证产品。具体命令及门禁范围见[验收说明](verification.md)。任务结构单独运行 `node tools/check-plan.mjs`。

交付顺序：同批更新专题与目录 → 结构检查 → 独立冷读 → 执行受影响命令/页面路径 → 关闭阻断 → 保存独立 hash 和真实报告 → 主集成者按可写范围提交 → 追加请求状态。不可改变旧 Txx、原发布关卡或历史证据；尚缺环境时如实标 blocked，不写 done。
